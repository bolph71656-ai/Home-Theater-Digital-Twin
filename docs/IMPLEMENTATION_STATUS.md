## プロダクト上の中心目標

HTDTの目的は単なる測定ビューアではなく、実測と履歴を使ってスピーカー配置・設定を改善する反復作業を支援すること。

最初の実利用シナリオは以下とする。

1. MLPでFL/FRの基準測定を行う。
2. マイクと条件を変えずに同条件再測定を行い、測定ばらつきを把握する。
3. 配置Aを記録する。
4. 一つの配置変更だけを行って配置Bを記録する。
5. 同じ測定条件で再測定する。
6. A/B差と同条件の繰返し差を同じ帯域で比較する。
7. 改善が再現した変更だけを次の基準へ採用する。

将来の「推奨位置」は、十分な実測がない段階で断定せず、次に試す候補として提示する。

## 実装状態

### M01: 最小起動基盤 — 開始

この変更で以下を導入する。

- Python 3.12向けFastAPIアプリ
- `/api/health` ヘルスチェック
- React/Viteの最小UI
- 開発時のsame-origin相当の`/api` proxy
- Python/Node依存バージョンの固定
- バックエンドの最小テスト
- Windows向けCI

M01ではSQLite、REW parser、Plotly、部屋編集、3D、REW APIはまだ実装しない。

## 次の作業

M01の起動・CIが通った後、M02へ進む。実REWファイルがまだないため、M02前半は仕様に沿った合成fixtureを用意し、以下を先に実装する。

- UTF-8/ASCII、BOM、CRLF/LF
- コメント/ヘッダー保持
- frequency / level / optional phase
- 周波数の正値・有限・厳密増加検証
- NaN/Inf、重複、逆順、欠損列の明示エラー
- phase_status = valid / absent / unknown

実REWデータが用意できた時点で、対象REW版の実出力をfixtureへ追加し、それをもって互換性を受入済みとする。
